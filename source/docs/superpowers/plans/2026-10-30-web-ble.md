# Web BLE Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Add read-only Web Bluetooth beside Wi-Fi without Artisan Bluetooth or helper software.

**Architecture:** Firmware frames the existing v1 status JSON into a custom notify-only GATT service; the browser reassembles it and applies the shared schema. Firmware and web tasks use the frozen wire contract and separate files; root owns integration, docs and release.

**Tech Stack:** Pinned Arduino ESP32 3.3.12 BLE library, C++17, Vue3/TypeScript/Vitest, Web Bluetooth.

**Spec:** `docs/superpowers/specs/2026-10-30-web-ble-design.md`

## Global Constraints

- Read-only; no Artisan BLE, commands, heartbeat or physical-output changes.
- Service/characteristic UUIDs, 8-byte header, 1..1023-byte JSON, 9..244-byte notifications are fixed by spec.
- No scanning without click; clear stale telemetry within3s; disconnect on hidden/dispose/switch.
- Preserve existing dirty files and flavor/import work. No commits to the shared local branch; publication helper owns only its separate Site checkout.
- User's narrowed instruction supplies the execution scope; routine implementation, tests and existing authorized publication proceed without another permission checkpoint.

## Review Focus

1. Native callbacks and main-loop access cannot race Controller or block its deadlines.
2. Cancellation during chooser/GATT promises cannot reconnect or leak device sessions.
3. Small MTU, dropped/duplicate/reordered fragments cannot yield mixed snapshots.
4. HTTPS capability and browser support must not reuse the broader Wi-Fi HTTP eligibility check.
5. BLE coexistence or disconnection cannot change Artisan ownership or its control lease.
