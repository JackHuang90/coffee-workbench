# 首次配网、修改网站与恢复

当前源码默认启用热点配网，两种构建仍只有 LOCKED / VIRTUAL_DEMO，物理输出始终禁用。以下是实现流程；尚未在真实开发板、手机或路由器上验收。

1. 初次上电，连接 `Coffee-Setup-XXXXXX`。每台设备有独立随机 WPA2 密码，保存在独立身份空间。成品应随设备提供标签/二维码；开发板首次使用可通过 USB 串口发送 `SETUP`（加换行）取得热点名、密码及实际入口。普通状态和启动日志不打印凭据。
2. 尝试系统弹出的配网页，或在完整浏览器打开 `http://192.168.4.1/`。页面全部由 ESP32 提供，不需要外网资源。
3. 扫描并选择 2.4 GHz 网络，或手填隐藏 SSID 和密码。地址默认 DHCP。固定地址需填写 IP、连续子网掩码、同网段且不同于设备的网关，以及 DNS。网络/广播地址、明显冲突会被拒绝；不能仅靠表单检测同网其他主机占用。
4. 填写允许的网站，一行一个完整 URL，最多四个。支持原有 HTTPS 网站；HTTP 只接受精确 `localhost`、127/8 回环 IPv4 与 RFC1918 私有 IPv4（10/8、172.16/12、192.168/16）。例如 `http://localhost:5173`、`http://127.0.0.1:3000`、`http://192.168.1.4:8080`。测试后显示去除路径、按协议去除默认 HTTP 80 / HTTPS 443 端口且主机小写的精确来源。公开版本不预填网站来源。请填写你实际打开工作台的来源；也可通过 `ROAST_DEFAULT_ORIGIN` 自行设置编译默认值。留空可完成配网，但跨来源网页读取被拒绝。不自动添加任何本机/内网来源；`localhost`、`127.0.0.1`、不同主机和不同端口都需要单独填写。来源支持 ASCII 主机/IPv4（国际域名请粘贴浏览器生成的 punycode）；此版不接受 IPv6 网站来源。HTTP 不接受公网域名/IP、`*.localhost` 子域、`.local` 名称、用户信息或通配符。IPv4 必须是无前导零的四段十进制，拒绝 `127.1`、整数、十六进制等浏览器可能重写的地址；端口范围为 1–65535。
5. 点击“测试连接”，最多等待 30 秒。候选只在内存中，不覆盖原配置。错误密码、连接超时或无效表单都不能保存未测试的候选。成功获得地址后，核对 IP、网关和规范化的网站来源，再点击“保存并完成”。
6. 保存成功后复制设备 IP，手机切回路由器 Wi-Fi；热点约 30 秒后关闭。保存失败会留在页面，允许重试，不报告成功。以后上电自动连接已保存网络，短时断线按有上限退避重试，不自动恢复控制会话，也不因路由器暂时离线自动开放热点。

公网网页直连仅支持 RFC1918 私有 IPv4（10.x、172.16–31.x、192.168.x），HTTP 80 固定状态路径。网页能否读取还取决于 HTTPS 托管策略和浏览器局域网权限；设备来源许可不是控制授权。桌面 Chrome/Edge、Android Chrome 是首批实测目标，iOS/微信内置浏览器仍需独立确认。保留本地桥接兼容方式，无需关闭浏览器安全检查。

## 热点网段冲突

热点候选网关依次为 `192.168.4.1`、`192.168.37.1`、`172.31.240.1`、`10.77.0.1`（均 /24）。已知固定配置或获得 DHCP 地址后，设备选择不与路由网段重叠的候选。静态配置冲突在测试响应中给出新入口，DHCP 冲突在状态中公告；留出约 10 秒后迁移，页面保持新入口提示并停止向旧地址轮询。切换可能中断当前手机请求；重新连接设备热点，查看其 DHCP 网关或通过本地 `SETUP` 查询新的实际入口，再打开页面。不能把 `192.168.4.1` 当作任何路由网络下都不变的承诺。设备保留候选状态；重新打开页面后须重新输入密码并测试，防止另一页面提交了不同候选。

## 恢复配网和灯态

RESET/EN 让芯片复位，不能由运行中的固件测量按住时间。RESET 普通重启保留网络设置。

设备正常启动后，先释放 BOOT，再长按约 5 秒，紫色快闪后松开，才执行一次恢复。50 毫秒消抖；短按、启动时一直按住、抖动不会清空配置。不在按住 BOOT 时软件重启，避免进入芯片下载模式。恢复检查写入/清除成功后回到热点；保留设备标识、热点密码和非配网业务数据。自定义网络/来源被清除，产品默认来源重新显示，可修改或删除。

| 灯态         | 意义                          |
| ------------ | ----------------------------- |
| 蓝色慢闪     | 等待配网                      |
| 黄色闪烁     | 尝试连接                      |
| 绿色低亮     | 已获得地址，或测试成功/已保存 |
| 红色间歇闪烁 | 测试、保存或日常重连失败      |
| 紫色快闪     | BOOT 达到阈值，等待松开确认   |

GPIO0 为低有效 BOOT；GPIO48 WS2812 暂按 GRB，低亮度12/255。用户图片是接线依据，实际颜色顺序、跳线和内存仍需真机核验。灯只表示网络状态，不表示传感器/执行器完成资格验证。

## 实现和接口边界

- `coffee-net` 双槽保存版本、提交序号、完整配置和校验。先写另一个槽并回读确认；断电后选择完整旧或新记录。清除通过新墓碑并移除旧槽；从不整片擦除 NVS。NVS 本身不保证密码静态加密。
- `coffee-id` 只保存独立热点身份。网页和 `/api/v1/status` 永不回显路由器密码。只有本地显式 `SETUP` 查询返回热点密码。
- `GET /setup/state` 返回热点会话值、候选/已提交状态和最多12条扫描结果；`POST /setup/scan` 开始异步扫描；`POST /setup/test` 接收 URL 编码配置；`POST /setup/save` 带 `revision=<本页测试返回的代数>`，只提交同一候选；其他页面替换候选后旧代数失效。测试期间编辑表单也必须重新测试。
- 配置必须处于热点模式，通过 AP 地址及 peer 子网进入；Host 精确匹配 AP IP（可带80端口）。所有 POST 还需 AP 页面 Origin 和每次热点新生成的 `X-Setup-Token`。路由器侧、跨站、DNS rebinding 主机名和重复敏感头被拒绝。
- 无 Origin 的旧状态读取兼容；只有状态 GET/OPTIONS 接受精确配置的 HTTPS 或允许的本机/内网 HTTP Origin，响应包含 `Vary: Origin`，没有通配符和 credentials。控制 POST 仍拒绝所有 Origin，原授权/租约不变。
- 控制 tick 始终在每轮网络工作前运行。HTTP 每步读/写最多64字节，门户正文4096字节独立于旧命令255字节。页面直接从 Flash 分段发送；无 Wi-Fi 连接等待循环。扫描和连接由主循环检查，不从异步事件线程操作控制器。
